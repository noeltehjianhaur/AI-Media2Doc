Video Transcript Upgrade Plan

Audio and Audio + Video modes, durable GitHub output records, live provider quota and balance telemetry, model fallback, and temporary-media cleanup.

Prepared: 2026-09-07. Status: proposal only. No application source code was modified while preparing this plan.

1. Decisions and Scope

Requirement Decision
Existing Audio transcription Retain unchanged as the default mode: obtain/extract MP3, send audio to ASR, retain local history and generated summary.
New Audio + Video mode Add an explicit user-selected mode. Gemini receives the original video and analyzes visual frames plus audio to capture spoken and on-screen information.
Output records Audio mode creates Markdown. Audio + Video creates an HTML record with selected screenshots and a static SVG flowchart when relevant.
GitHub destination Publish an opt-in output bundle to the private repository noeltehjianhaur/AI-Media2Doc-Output, one commit per completed record.
Temporary media Delete R2/Gemini temporary media after successful processing and optional publication. Keep task text/HTML locally and in GitHub output when publishing is enabled.
Provider quota and balance Retrieve live provider-reported values for Gemini, OpenRouter, and Cloudflare through server-side API adapters where the provider exposes an authorized endpoint. Refresh on page load, after transcript completion, and on explicit user request.
Feasibility: all requested features are technically feasible. Audio + Video requires the native Gemini SDK/Files API; it cannot be fully implemented through the current OpenAI-compatible chat-completions call alone.

2. Current Workflow Baseline

The existing application is intentionally audio-only for transcription. Local uploads use browser ffmpeg to run -map a and create an MP3. Parsed links use yt-dlp with bestaudio/best and ffmpeg MP3 conversion. The backend sends only input_audio to Gemini. The app's current screenshot markers are post-processing decoration, not visual evidence supplied to the transcription model.

Existing local history is retained in browser IndexedDB. It stores each task's source name, mode/style, transcript, generated content, and created time. R2 currently stores extracted audio objects, but no automatic deletion runs after a completed task.

3. User-facing Transcript Source Modes

Mode Input handling Transcript behavior Persistent output
Audio Keep current MP3 extraction for uploaded video, and audio-only yt-dlp flow for links. Automatic spoken-language detection; transcript contains spoken content. Target-language translation remains optional. Markdown .md.
Audio + Video Obtain original video; uploaded files go to Gemini Files API. Public YouTube URLs are passed directly to Gemini when supported. Other links use yt-dlp to obtain video + audio. Structured, timestamped content with spoken words, on-screen text, tool names, UI actions, diagrams, and visual context. HTML .html, plus images and an SVG flowchart only when generated.

The mode selector should be a segmented control placed beside the source input. Default: Audio. Audio + Video should show estimated duration/size and a notice that it takes longer and consumes more multimodal quota.

4. Content-derived Output File Names

Do not use raw upload names, opaque IDs, or a generic title. After transcription, call the selected text-capable model with a constrained naming prompt using the transcript and visual summary. The model returns a short title only; the backend transforms it into a safe file stem.

Requested title: "Building HTML Artifacts with Local Agents"
Sanitized stem:  building-html-artifacts-local-agents
Timestamp:       20260907-214530

Audio:           building-html-artifacts-local-agents_20260907-214530.md
Audio + Video:   building-html-artifacts-local-agents_20260907-214530.html

Filename rules: 6-12 meaningful words; lowercase ASCII slug; remove invalid path characters; collapse repeated dashes; maximum 90 characters before the timestamp; use a short content hash only to resolve collisions. The timestamp is UTC in YYYYMMDD-HHMMSS form.

Source mode GitHub output location Record metadata
Audio records/audio/YYYY/MM/<content-title>_<datetime>.md Title, created UTC, source mode, original upload name, detected language, target language, style, transcript, generated summary, model/provider usage.
Audio + Video records/audio-video/YYYY/MM/<content-title>_<datetime>/index.html Same metadata plus visual transcript, screenshots, diagram, visual-analysis model, and processing mode.
Source link rule: write a Source URL row only for a parsed-link task. For uploaded video/audio tasks, omit that row completely; record the original uploaded file name only.

5. Audio + Video Processing Design

  1. Create a task record first; show a durable queued/processing/completed/failed state.
  2. For an upload: retain the original video temporarily in R2 or pass it from backend storage into Gemini Files API. Do not discard the existing MP3 route; it remains the Audio-mode route.
  3. For a YouTube link: use Gemini's direct public YouTube URL support when available. Avoid yt-dlp full-video download in this case.
  4. For Rednote/Facebook/other supported links: yt-dlp downloads video + audio, merges to a temporary compatible video if needed, then passes it to Gemini Files API.
  5. Gemini video analysis returns schema-validated JSON: detected language, segments, spoken text, on-screen text, visual actions, important timestamps, and a flowchart specification.
  6. Capture only model-selected high-value frames using ffmpeg. Validate the diagram specification, render a static SVG, and render sanitized HTML without model-provided JavaScript.
  7. Build/publish the output record if the user opted in; then clean up temporary media.

Use Gemini agentic video processing for long videos and static mode for short clips where full timeline coverage matters. Gemini's published documentation states static mode samples frames at 1 FPS by default, while agentic mode selectively loads timeline data and can use substantially fewer tokens for long-form content.

6. HTML Record Format

HTML is appropriate for the XHS-style visual process record in the attached screenshot because it can retain process blocks, figures, captions, tables, and linked media. GitHub will sanitize untrusted HTML, so output must not depend on scripts or embedded Mermaid JavaScript.

  1. Use a conservative, self-contained HTML/CSS template authored by the application.
  2. Include title, metadata, executive summary, timestamped transcript, on-screen context callouts, screenshots, captions, static SVG flowchart, and source information when applicable.
  3. Store screenshots under an images/ directory and use relative paths.
  4. Store a manifest.json next to index.html with hashes, models used, usage data, and publication commit SHA.
  5. Escape/sanitize all transcript and model text before inserting it into HTML.

7. Live Provider Balance and Quota

Add a Provider Usage panel for Gemini, OpenRouter, and Cloudflare. Each provider card shows its latest provider-reported balance, quota, or usage values, the time retrieved, and a status of available, unsupported, not_configured, or error. A single Refresh button updates all cards; an individual provider failure must not prevent the other cards from updating.

Provider Live API source and values Limitations Required behavior
Gemini Use an authorized Google Cloud Service Usage/Monitoring API when the configured Gemini project and credentials expose quota limits and current usage. Continue collecting model response token metadata, selected model, latency, result, and retries for every request. The Gemini API key alone does not provide a universal endpoint for remaining AI Studio Free-tier RPM/TPM/RPD. Google Cloud quota metrics vary by project, API, model, region, and credential permissions. Attempt the live project-level lookup when Google Cloud telemetry credentials are configured. Display the returned metric names, limits, usage, and reset/window metadata. Otherwise return unsupported or not_configured with an AI Studio quota-dashboard link; never present a configured estimate as a real-time provider value.
OpenRouter Call the authorized credits endpoint and display total credits, used credits, and computed remaining credits. Retain native token usage, response cost, and generation statistics for completed requests. The credits endpoint requires a server-side OpenRouter management key; an inference key may not have permission to read account credits. Use optional OPENROUTER_MANAGEMENT_KEY credentials and return not_configured when absent. Label values with the currency/unit supplied by OpenRouter and preserve per-task cost in the usage ledger.
Cloudflare R2 Call Cloudflare's authorized account/R2 analytics API and display available storage bytes, Class A operations, Class B operations, egress, and the provider's reporting interval. Continue recording application-observed uploads, downloads, deletes, and object sizes. Cloudflare analytics can be delayed and is usage rather than a monetary account balance. Exact invoice totals, plan allowances, and remaining free-tier amounts may not be exposed by the same API and must not be inferred without current plan limits. Use server-only account ID and scoped analytics token. Show provider-reported usage separately from locally measured task bytes and expose the R2 dashboard link as the billing source of truth.

Refresh lifecycle

  1. Fetch all three providers once when the web application page loads.
  2. Fetch all three providers after a transcript task reaches completed, after final provider usage metadata has been persisted. Do not refresh for every polling response.
  3. The Refresh button starts the same fetch on demand, shows an in-progress state, and is disabled while that refresh is running.
  4. Prevent duplicate requests when page-load and task-completion triggers overlap. Use a short server-side cache and request coalescing; manual refresh may bypass the cache but must still be rate-limited.
  5. Retain the last successful values when a later refresh fails, mark them stale, show the retrieval time, and provide a concise provider-specific error without exposing secrets.

Backend contract and security

Add GET /api/v1/provider-usage for the normal cached refresh and POST /api/v1/provider-usage/refresh for a rate-limited manual refresh. The response contains a result per provider with status, source, retrieved_at, reporting_period, typed metrics, optional dashboard URL, stale state, and a safe error code. Provider API calls run concurrently with independent timeouts.

Usage data is informational and must be labeled provider-reported or locally measured. Estimated values may be shown only in a separately labeled field and never as live balance/quota. Gemini, OpenRouter, and Cloudflare credentials remain server-side, are excluded from logs and API responses, and use the narrowest read-only scopes available.

8. Capability-verified Model Rotation

Do not auto-cycle through every visible Gemini model. The screenshots show many models with zero available quota or unrelated capabilities (image generation, TTS, music, agents). A model shown in AI Studio is not automatically appropriate, enabled, free, or compatible with the task.

The screenshot shows your active Free-tier gemini-3.6-flash at 4 / 5 RPM and 6.7K / 250K TPM. Therefore, an immediate fifth concurrent request may be allowed but a sixth in the same minute should wait or be routed according to the configured policy. The RPD number is not legible in the supplied screenshot and must be treated as account-specific.

Create a versioned, server-side capability manifest. Each candidate must declare: enabled status, stable/preview status, supported input modalities, Files API/video support, structured-output support, region eligibility, configured quota snapshot, provider price, and role.

Role Recommended Gemini chain: higher capability to lower Eligibility gate
Audio transcript gemini-3.5-transcribe → gemini-3.6-flash → explicitly configured compatible fallback Must accept audio, support language detection, and be enabled for the project. Never send audio to a text-only model.
Audio + Video analysis gemini-3.8-flash → gemini-3.7-flash → gemini-3.6-flash → gemini-3.5-flash-lite Must support Gemini Files API/native video analysis and the selected processing mode. Use only models that are actually enabled and have usable quota.
Translation, title, Markdown/HTML rendering gemini-3.8-flash → gemini-3.6-flash → gemini-3.5-flash-lite → OpenRouter text chain Text/structured-output support only; lower model is acceptable for filename generation and template rendering.

Rotation rules: rate-limit errors (429 RESOURCE_EXHAUSTED) enqueue with reset-aware backoff; temporary capacity failures (503) retry once or twice with jitter before moving to the next eligible model; authentication, validation, content policy, and unsupported-modality errors do not rotate blindly. Log every attempt and selected model in task metadata.

For OpenRouter, fetch the model catalog periodically from its models API, but restrict candidates to a manually approved allow-list. OpenRouter offers route fallback and free :free variants, but free availability/rate limits are dynamic. The plan must not treat openrouter/free as a guaranteed quality, modality, or production fallback.

10. Temporary-media Cleanup

  1. Store temporary media under temporary/<task-id>/.
  2. Track each object and its purpose: extracted MP3, downloaded original video, rendered frame, intermediate merged video.
  3. After completed transcript, completed HTML/Markdown rendering, and successful optional GitHub publication: delete all temporary R2 objects and Gemini Files API objects.
  4. On terminal failure: retain error metadata; delete temporary objects in a final cleanup block.
  5. Add a user setting Keep source media, default false. Only explicit opt-in disables cleanup.
  6. Configure an R2 lifecycle rule as a failsafe to delete temporary/ objects after 24 hours.

Deleting media is safe for normal history because local IndexedDB retains transcript/summary data and the optional output repo retains record artifacts. Deletion is not safe if the user expects future video re-analysis; the UI should state that re-analysis requires uploading/parsing the source again unless Keep source media is enabled.

11. GitHub Output Publishing

Publishing is feasible. Add a server-only GitHub service using Git Data API so a whole record bundle is committed atomically instead of creating one commit per screenshot.

GITHUB_OUTPUT_ENABLED=false
GITHUB_OUTPUT_REPOSITORY=noeltehjianhaur/AI-Media2Doc-Output
GITHUB_OUTPUT_BRANCH=main
GITHUB_OUTPUT_TOKEN=github_pat_...  # Fine-grained: Contents Read/Write on this repo only
  1. User enables Publish for a task; default remains off.
  2. Backend produces Markdown or HTML bundle plus manifest.
  3. Backend derives a safe LLM title and deterministic destination directory.
  4. Backend makes one tree, commit, and branch-reference update.
  5. Task stores output commit SHA, repository URL, output path, and status.
  6. A failed publish can retry from saved task data without repeating AI processing.
